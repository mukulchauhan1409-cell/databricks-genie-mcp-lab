# Contributing

Thanks for your interest in improving this project.

## What to contribute

Useful contributions include:

- Documentation improvements
- Reproducible Databricks examples
- Additional Genie business questions
- MCP validation coverage
- Unity Catalog governance examples
- Corrections to outdated Databricks behavior or documentation references

## Before submitting a change

1. Keep examples reproducible with the documented demo dataset where possible.
2. Do not commit access tokens, credentials, workspace secrets, or personal identifiers.
3. Clearly document any Databricks feature, endpoint, or behavior that depends on a specific release.
4. Update the relevant documentation when changing the validation flow.
5. Keep claims supported by either reproducible project evidence or official Databricks documentation.

## Pull requests

Please describe:

- What changed
- Why it changed
- How it was validated
- Any limitations or version-specific behavior

Small, focused pull requests are preferred.
